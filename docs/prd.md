# 批量代码文件 AI 分析工具 - 产品需求文档（v1.1）

> 修订定位：本产品保持为“批量文件分析工具”，不承担 Git 提交过程重建、程序员编码顺序推断或自动修改源代码。
> 本版重点补充：运行批次、文件变更检测、暂停与恢复、崩溃恢复、安全边界、并发规则、数据模型和可执行验收标准。

## 1. 产品目标

提供一个本地桌面客户端：用户可登记和管理多个本地代码仓库；在选定仓库后，工具筛选出适合发送给模型的真实项目文件，并针对每个文件独立调用兼容 OpenAI Responses API 的模型。用户可以统一设置提示词和模型，也可以按文件设置覆盖值；随后查看 Markdown 返回结果、请求统计、失败原因，并进行单项或批量重试。

典型用途包括：

- 批量解释代码文件的职责、数据流和模块关系；
- 按统一模板提取接口、依赖、风险或技术债信息；
- 生成注释建议、测试建议或代码审查报告；
- 对大型仓库进行逐文件结构化分析并导出结果。

产品只负责“扫描文件—构造请求—调用模型—保存结果—管理运行记录”的闭环，不承诺模型分析必然正确，也不直接修改源代码。每次正式批量执行都必须形成一个可追溯、可恢复的“运行批次（Run）”。


## 2. 范围与边界

### 2.1 本期范围

- 导入一个本地文件夹，或将文件夹拖入窗口。
- 管理多个已登记的本地仓库，并在它们之间切换。
- 解析并以树形表格列出待处理的项目文件。
- 支持重新扫描，并识别文件新增、修改、删除、不可读取和结果过期状态。
- 支持模型连接配置、并发配置、请求超时、失败自动重试和输出目录配置。
- 支持可复制的 API 配置档案，以及按顺序切换的主备 API 兜底链路。
- 支持项目默认提示词和模型，以及单文件提示词、模型覆盖。
- 支持常用提示词管理、AI 辅助生成提示词，以及单文件随机测试。
- 支持从仓库 README、`AGENTS.md` 等项目文档构建项目上下文，以提升单文件分析的可解释性。
- 创建正式运行批次，并冻结该批次的提示词、模型、上下文版本、文件哈希和 API 路由快照。
- 并发执行每个文件对应的 AI 请求。
- 支持暂停、继续、取消、停止批次、单项重试和筛选后的批量重试。
- 支持应用异常退出后的未完成批次恢复，且不得自动重复计费请求。
- 查看 Markdown 结果、请求元数据、失败任务筛选和完整请求尝试历史。
- 将结果及任务元数据写入按运行批次隔离的输出目录。
- 默认排除常见密钥文件，并对疑似敏感内容、符号链接和危险 Markdown 做安全处理。

### 2.2 非本期范围

- 不编辑、格式化或覆盖源代码文件。
- 不承诺代码仓库可编译、测试可通过或模型分析结果正确。
- 不推断 Git Commit 的真实开发顺序、文件创建顺序或程序员思考过程。
- 不在本期实现多个仓库混合为同一运行批次。
- 不在本期实现团队协作、云端任务队列、账号体系或远程仓库托管。
- 不在本期实现超大文件自动分段、跨文件向量检索或完整代码依赖图分析。
- 不在本期兼容所有模型协议；首期以 OpenAI Responses API 适配层为准。

### 2.3 核心概念

| 实体 | 定义 | 关键规则 |
| --- | --- | --- |
| 项目（Project） | 一个已登记的本地代码仓库 | 保存项目默认设置、筛选规则和历史运行入口 |
| 文件记录（FileRecord） | 扫描得到的一个仓库文件 | 保存路径、大小、修改时间、内容哈希和源文件状态 |
| 运行批次（Run） | 用户一次正式点击执行所创建的批量分析 | 创建时冻结配置快照；不同批次的结果和统计互相隔离 |
| 文件任务（Task） | 某个 Run 中对一个文件进行一次分析 | 关联一个文件快照，可拥有单文件提示词或模型覆盖 |
| 请求尝试（Attempt） | Task 实际向某个 API 档案发送的一次网络请求 | 自动重试和主备切换都会新增 Attempt，不覆盖历史 |
| 上下文版本（ContextVersion） | 一次生成或人工编辑后的项目上下文摘要 | Run 创建时固定版本，自动重试继续使用原版本 |

### 2.4 作用域与优先级

1. 客户端全局设置提供新项目默认值，但不得静默改写既有项目。
2. 项目设置影响之后创建的 Run，不得影响已经创建或正在执行的 Run。
3. 单文件覆盖优先于项目默认值。
4. Run 创建时将有效提示词、模型、上下文、文件哈希、并发和 API 路由保存为快照。
5. 自动重试必须使用原 Task 快照；需要使用最新项目配置重新分析时，应创建新 Run，或明确执行“使用最新配置重新生成”。
6. 本期同一时间只允许一个 Run 处于执行、暂停中或取消中状态；用户仍可切换项目并查看其他项目历史。


## 3. 主要流程

1. 用户选择本地代码目录，或将目录拖入导入区域；客户端登记项目并创建或加载项目配置。
2. 工具扫描目录，递归读取适用的 `.gitignore`，执行内置排除、自定义排除、敏感文件和大小限制，生成文件记录与导入报告。
3. 用户在“提示词”页选择、编辑或生成项目默认提示词，并可随机抽取一个文件测试。
4. 用户在“API 配置”页选择主 API 档案和备用档案，设置默认模型、并发数、请求超时、最大输出 Token、重试策略与输出根目录。
5. 用户可针对特定文件设置提示词或模型覆盖，也可以排除不希望发送的文件。
6. 用户点击“开始分析”后，系统执行启动前检查，并展示任务数量、疑似敏感文件、预计输出目录和当前配置摘要。
7. 用户确认后创建 Run；系统冻结文件内容哈希、提示词、模型、项目上下文版本、API 路由和重试配置，并生成独立运行目录。
8. 调度器按照并发限制发送请求；每次网络请求均记录为 Attempt。用户可以暂停、继续或取消 Run。
9. 用户在任务表格中查看状态、Markdown 结果、Token、耗时、主备切换过程和错误信息。
10. 用户可以对失败、取消或已完成的任务执行重试或重新生成；自动重试仍属于原 Run，使用最新配置重新生成则创建新的 Task 版本或新 Run。
11. 用户重新扫描项目时，系统识别新增、修改和删除文件，并标记已有结果是否过期，不自动重新发送请求。
12. 应用异常退出后，重启时显示未完成 Run；原处理中任务标记为“已中断/结果未知”，必须由用户决定是否重新排队，系统不得自动重发。


## 4. 界面需求

### 4.1 客户端项目管理

客户端使用左侧项目栏和右侧项目工作区的布局。任何提示词应用、任务执行、筛选、重试或结果预览均只作用于当前选中的项目。

左侧项目栏要求：

- 列出已登记仓库的名称、根目录、最近打开时间和任务摘要（例如失败数、进行中数）。
- 提供“添加项目”操作，支持选择目录或拖入目录；已登记目录再次导入时应定位至已有项目，而非重复创建。
- 支持项目搜索、切换、重命名显示名称和从客户端列表移除。
- “移除项目”仅删除客户端登记信息，不删除源代码目录、输出目录或已生成结果；需明确二次确认。
- 找不到原目录时标记为“路径不可用”，保留历史任务和输出记录，并允许用户重新定位本地目录或移除项目。
- 当前选中的项目名称、根目录和项目状态应在右侧工作区顶部持续可见。

仓库之间的规则：

- 每个项目拥有独立的文件清单、筛选规则、任务、单文件提示词/模型覆盖和输出目录。
- 同一时刻只展示和操作一个项目；本期不支持跨项目混合执行、跨项目筛选或跨项目批量重试。
- 用户切换项目时，当前项目的文件列表、筛选状态、Run、Task 和结果必须保留；不得自动重新扫描或重新发送请求。
- 若当前存在活动 Run，切换项目不会停止该 Run；客户端顶部或侧栏必须持续显示全局运行状态和返回入口。
- 本期同一时间只允许一个活动 Run。其他项目可以编辑配置和查看历史，但“开始分析”按钮应禁用并说明当前正在执行的项目。
- 新增项目默认继承客户端默认提示词、客户端默认模型和全局筛选规则；继承后可在项目内独立修改。
- 首次登记可写入的仓库时，客户端在仓库根目录创建 `.batch-analysis/project.json`；后续再次添加或打开同一路径时优先加载该文件，以恢复项目设置。
- 客户端不得自动修改仓库的 `.gitignore`。若 `.batch-analysis/` 未被忽略，应提示用户自行决定是否加入忽略规则。

作用域定义：

| 作用域 | 可复用资源 | 说明 |
| --- | --- | --- |
| 客户端全局 | 常用提示词库、API 配置档案、新项目默认值、默认筛选规则 | 可被所有项目选择或继承；API 档案可复制；修改后不应静默改写既有项目 |
| 项目 | 当前项目默认提示词、默认模型、筛选规则、输出根目录、文件记录和历史 Run | 仅影响当前仓库；项目设置只影响之后创建的 Run |
| 单文件配置 | 提示词和模型覆盖、是否纳入下一次 Run | 优先于项目默认值；Run 创建后转换为不可变快照 |

### 4.2 顶部第一个 Tab：提示词

顶部 Tab 固定顺序为：`提示词`、`API 配置`。进入应用后默认打开“提示词”Tab，使用户先明确批量处理目标，再配置调用服务。

#### 当前项目默认提示词

- 提供一个当前项目默认提示词的多行输入框，以及“保存为项目默认”和“应用到全部文件”操作。输入框中的未保存内容可用于随机测试，但不会影响既有项目设置。
- 默认值为结构化解释模板；项目上下文可用时，模板要求结合该上下文，避免孤立地解释语法。建议默认内容如下：

```text
请结合提供的项目上下文，用通俗但准确的语言解释当前代码文件。
请说明：
1. 该文件在项目中的核心职责；
2. 关键输入、输出、状态或数据流；
3. 它与哪些模块或功能协作，以及它为何存在；
4. 修改或缺失它可能带来的影响。
如无法从上下文或代码中确认，请明确说明不确定性，不要臆测。
```

- 文件列表中的默认行不重复保存提示词全文，而是显示“继承项目默认提示词”；只有用户逐行修改时才保存 `promptOverride`。
- 点击“保存为项目默认”只更新项目默认提示词，所有未覆盖文件立即显示新的继承值；点击“应用到全部文件”则在保存默认值后，询问是否清除全部单文件提示词覆盖。不得静默覆盖。
- 新扫描出的文件默认继承项目默认提示词，不需要用户再次点击应用。
- Run 创建时，将每个文件最终生效的提示词保存为 Task 快照；Run 创建后的项目提示词修改不影响该 Run。
- 逐行修改提示词后，该行标记为“已覆盖”，并提供“恢复项目默认”操作。

#### 常用提示词

- 在当前项目默认提示词输入框旁提供“常用提示词”下拉选择器。
- 选择一项后，仅将其内容填入输入框；用户仍需点击“保存为项目默认”或“应用到全部文件”才会修改项目配置。
- 用户可将当前输入框内容以“名称 + 内容”的形式保存为常用提示词，并可编辑、删除用户创建的常用提示词。
- 预置提示词可随应用提供，但不得被删除；用户创建的提示词应持久化在本地配置中。
- 保存时，名称不能为空；同名项需提示用户覆盖、重命名或取消，不能静默覆盖。

#### 生成提示词

- 提供“生成提示词”按钮，打开生成面板。
- 用户输入本次批量处理目标、希望的输出格式或限制条件后，系统通过当前 API 配置、当前项目默认模型和项目上下文摘要生成一个候选提示词。
- 候选提示词在生成面板中可继续编辑；点击“使用此提示词”后填入当前项目默认提示词输入框，但不自动应用到任务。
- 用户可将候选提示词直接保存为常用提示词。
- 未配置可用 API Key、Base URL 或当前项目默认模型时，按钮应禁用并说明需先在“API 配置”Tab 完成设置。

#### 项目上下文

项目上下文用于让模型理解当前文件在整个仓库中的位置，默认开启。它既参与“生成提示词”，也参与随机测试和正式的单文件分析请求。

- 导入或重新扫描项目时，自动发现仓库根目录下的 `README`、`README.md`、`README.*` 和 `AGENTS.md`；用户可额外选择其他文本文件作为上下文资料。
- 界面展示发现的上下文文件、相对路径、大小、是否启用和最后修改时间；用户可勾选、取消勾选、添加或移除额外资料。
- 系统从启用资料中生成“项目上下文摘要”，应覆盖项目用途、主要模块、架构/数据流、技术栈、代码约定及与本次分析相关的约束。
- 默认提示词的候选构造应要求模型结合项目上下文，说明当前文件的职责、关键输入输出或数据流、与其他模块的关系，以及该文件缺失或修改时可能影响的行为；避免只复述函数或语法。
- 上下文摘要模型默认沿用项目默认模型，也允许项目单独指定；提示词生成模型采用相同规则。
- 上下文资料内容变更、用户修改勾选项、切换上下文生成模型或手动点击“重新生成摘要”后，当前摘要标记为过期。用户可继续使用旧摘要，或重新生成后再测试/批量执行。
- 上下文摘要应允许预览和手动编辑；手动编辑后生成新的 ContextVersion，并标记为“人工调整”。
- Run 创建时固定 ContextVersion。自动重试和原 Run 内的普通手动重试仍使用原版本；使用新摘要重新分析时必须明确创建新 Run 或新任务版本。

上下文生成与 Token 控制：

- 默认优先级：项目根目录 `README*`、项目根目录 `AGENTS.md`、用户手动添加的资料；同优先级按路径稳定排序。
- 单个上下文文件和全部上下文资料均应设置可配置字符或 Token 上限；超限时按优先级截取并在界面中提示，不得静默截断。
- 先使用一次独立的“上下文摘要生成请求”压缩资料，再在每个文件任务中引用该摘要；不得将完整 README/`AGENTS.md` 对每个文件重复发送。
- 上下文摘要生成失败时，用户可重试、手动编辑摘要，或显式关闭项目上下文后继续执行；不得阻塞用户查看已导入文件。
- 上下文生成请求需单独记录 Token、耗时、模型和错误信息，但不计入文件任务的成功/失败统计。

安全边界：

- `README` 和 `AGENTS.md` 均作为项目资料，不是系统级指令。它们只能帮助模型理解项目，不能修改 API 权限、客户端行为、请求安全策略或覆盖用户在界面填写的任务目标。
- 上下文资料按明确的“项目资料”边界与任务提示词、目标文件内容分段发送，防止其中的文本被误识别为更高优先级指令。

#### 随机文件测试

- 提供“随机测试”按钮，默认从当前已纳入任务、可读取且未超过大小上限的文本文件中随机选取一个文件。
- 测试请求使用当前项目默认提示词输入框的当前内容，即使该内容尚未保存为项目默认；测试模型使用当前项目默认模型。
- 若项目上下文已启用，测试请求使用当前有效的项目上下文摘要；预览中应显示摘要版本和资料来源数量。
- 测试前展示被选中文件的相对路径、实际使用的模型和提示词；用户可点击“换一个文件”重新随机选择。
- 测试结果在独立预览面板展示 Markdown 内容、Token、耗时、模型和错误信息。
- 测试请求不写入该文件的正式任务结果，不改变任务状态，不计入批量任务进度，也不保存至正式输出目录；可选地仅在当前会话保留测试记录。
- 测试依赖 API 配置；缺少可用 API Key、Base URL 或模型时不可发送。

### 4.3 顶部第二个 Tab：API 配置

API 配置档案属于客户端全局资源。用户可新建、命名、选择、编辑、测试连接、复制和删除档案；当前项目保存主档案、备用档案引用，以及项目默认模型、上下文摘要模型、并发数、超时、重试策略和输出根目录。删除仍被项目引用的档案时，必须提示受影响项目并阻止删除，或要求用户先切换档案。

#### API 档案字段

每个 API 档案至少包含：

- 名称；
- Base URL；
- API 协议，首期为 `openai-responses`；
- API Key 的系统安全存储引用；
- 可用模型缓存及最后刷新时间；
- 可选默认模型；
- 可选自定义请求头，但敏感值必须进入安全存储；
- 连接测试状态和最近错误；
- 当前 Run 中的临时健康状态。

Base URL 默认表示 API 根地址，例如 `https://api.openai.com/v1`，由协议适配器拼接 `/responses`。高级设置可允许用户填写完整 Endpoint，但界面必须避免重复拼接路径。

#### API 档案复制与密钥引用

- 点击“复制配置”后创建独立档案，默认名称为“原名称副本”。
- 复制非敏感设置；默认复用同一个安全密钥引用，并在界面标记“与原档案共享密钥”。
- 用户在副本中修改 API Key 时，应创建新的安全密钥记录，不得修改原档案密钥。
- 删除档案时，只能删除该档案引用；仍被其他档案引用的安全密钥不得被删除。
- API Key 在界面中仅脱敏显示，复制、日志、错误详情和导出数据中均不得出现明文。

#### 主备 API 路由

- 当前项目可选择一个主 API 档案，并添加零个或多个备用档案。
- 备用档案支持拖拽排序、启用/停用和移除。
- 每个备用档案可指定模型策略：`沿用任务模型` 或 `使用该档案默认模型`。
- 若沿用任务模型，但备用档案不支持该模型，则记录“模型不可用”并尝试下一档案。
- 若使用档案默认模型，Task 详情必须明确记录实际模型发生切换。
- 随机测试、提示词生成、上下文摘要生成和正式文件任务均使用同一套路由逻辑，但各自统计相互独立。

#### 自动重试、健康状态与切换规则

1. 网络超时、连接失败、`429` 和 `5xx` 先在当前档案内重试；优先遵循响应中的 `Retry-After`。
2. 未提供 `Retry-After` 时，默认等待序列为 5 秒、10 秒、20 秒，并加入约 ±20% 随机抖动；项目可配置最大重试次数。
3. `401` 视为档案认证失败：当前 Run 中将该档案标记为不可用，后续任务直接跳过，直到用户重新测试或新建 Run。
4. `403` 必须结合服务错误码分类：模型权限问题仅影响对应模型；账户、区域或认证权限问题可影响整个档案；内容策略拒绝只影响当前任务。
5. 模型不存在、模型无权限或不兼容时，不对当前档案重复重试，按备用链路继续。
6. 参数错误、文件过大、上下文超限、敏感内容阻止和用户取消等与服务档案无关的错误，不得切换备用档案。
7. 同一档案连续出现 3 次连接失败或 `5xx` 时，在当前 Run 中进入 60 秒临时冷却；冷却期间任务可直接尝试备用档案。
8. 主档案及全部备用档案均失败后，Task 状态为失败，错误详情汇总每次 Attempt 的档案名称、模型、耗时、状态码和脱敏原因。

#### 请求与执行配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| 主 API 档案 | 当前项目优先使用的服务连接配置 | 空 |
| 备用 API 档案 | 有序兜底配置，支持模型策略 | 空 |
| 当前项目默认模型 | 新文件和未覆盖文件默认使用的模型 | 空 |
| 上下文摘要模型 | 默认沿用项目默认模型，也可独立设置 | 沿用项目模型 |
| 并发请求数 | 文件 Task 同时在飞的最大网络请求数 | `5` |
| 请求超时 | 单次 Attempt 的网络超时时间 | `120` 秒 |
| 自动重试次数 | 每个档案内可重试失败的最大次数 | `1` |
| 重试等待 | 优先 `Retry-After`，否则指数退避 | `5` 秒起 |
| 最大输出 Token | 单个文件分析允许的最大输出 | `4096` |
| 流式返回 | 首期关闭，以降低恢复和重试复杂度 | 关闭 |
| 输出根目录 | 所有 Run 输出目录的父目录 | 空 |

本期并发规则：

- 同一时间只允许一个活动 Run，因此“并发请求数”同时也是客户端批量任务的全局在飞上限。
- 提示词生成、上下文摘要生成和随机测试也必须经过统一请求调度器；当活动 Run 已占满并发槽位时进入辅助请求队列。
- 用户将并发数从高值调低时，不中止已发送请求，但不得再派发新请求，直到在飞数量降到新上限以下。

若输出根目录为空，默认使用输入目录同级的固定分析根目录：

```text
输入：F:/code/github/07/mastra
输出根目录：F:/code/github/07/mastra-batch-analysis
某次 Run：F:/code/github/07/mastra-batch-analysis/runs/20260715103825-run-a1b2c3
```

时间戳只在创建 Run 时生成。获取模型失败时，必须保留手动输入模型名称的能力，并展示可复制的脱敏错误原因。


### 4.4 文件筛选、敏感文件与重新扫描

文件导入区域或独立的“文件筛选”配置应包含：

| 项目 | 规则 |
| --- | --- |
| 内置排除目录 | 默认排除依赖、构建产物、缓存、版本控制和本工具输出目录 |
| 内置排除后缀 | 默认排除二进制、压缩包、媒体、字体、锁文件和常见数据库文件 |
| 读取 `.gitignore` | 默认开启；递归读取仓库内适用的 `.gitignore`，尽可能遵循 Git 忽略语义 |
| 排除文件夹 | 用户可追加目录名称或相对路径模式 |
| 排除文件后缀 | 用户可追加后缀，例如 `.log`、`.csv` |
| 包含文件后缀 | 可选；非空时仅保留指定后缀，仍受全部排除规则限制 |
| 文件大小上限 | 默认 `256 KB`；超限文件不创建 Task，并在导入报告中说明 |
| 最大文件数量 | 默认 `10,000`；超限时停止创建新文件记录并要求用户缩小范围 |
| 敏感文件保护 | 默认开启；排除常见密钥文件，并扫描疑似秘密模式 |
| 符号链接 | 默认不跟随；指向仓库外部的链接始终禁止读取 |
| 隐藏文件 | 默认纳入规则判断，但仍受敏感文件与排除规则限制 |

内置排除目录建议至少包含：

```text
.git, .svn, .hg, node_modules, vendor, dist, build, out, target,
.next, .nuxt, .cache, coverage, __pycache__, .pytest_cache, .idea, .vscode,
.batch-analysis
```

工具必须识别自己的输出根目录；若用户将输出目录设置在仓库内部，需明确警告并自动加入当前项目排除规则，避免把分析结果再次作为源文件发送。

内置排除后缀建议至少包含：

```text
.zip, .tar, .gz, .rar, .7z, .exe, .dll, .so, .dylib, .bin,
.png, .jpg, .jpeg, .gif, .webp, .ico, .mp3, .mp4, .mov, .pdf,
.woff, .woff2, .ttf, .otf, .lock, .db, .sqlite, .sqlite3
```

默认敏感文件模式建议至少包含：

```text
.env, .env.*, *.pem, *.key, *.p12, *.pfx, *.keystore,
id_rsa, id_ed25519, credentials.json, secrets.json, .npmrc, .pypirc
```

敏感内容检测至少覆盖私钥头、常见云服务访问密钥、GitHub Token、Bearer Token、数据库连接串和高熵疑似密钥。发现疑似敏感内容时，默认阻止该文件进入 Run；用户必须查看风险类型并明确确认，且日志不得保存命中的秘密原文。

扫描逻辑不能只依赖后缀，应组合使用：

1. 路径和后缀规则；
2. 文件头或内容的二进制检测；
3. 编码检测，首期至少支持 UTF-8、UTF-8 BOM；
4. 文件大小与预估 Token 检查；
5. 敏感文件和敏感内容检查。

无法可靠解码的文件标记为“编码不支持”，不得以错误字符静默发送。Git Submodule 默认只展示为特殊目录，不自动递归扫描；Git LFS 指针文件应标记为 LFS 指针而非真实源码。

文件筛选优先级：

1. 阻止仓库外部符号链接和路径逃逸。
2. 排除内置目录及其子目录。
3. 应用递归 `.gitignore` 规则。
4. 应用用户自定义排除目录、路径模式和后缀。
5. 应用敏感文件和敏感内容规则。
6. 应用二进制、编码和大小限制。
7. 若配置“包含文件后缀”，仅保留匹配文件。

`.gitignore` 应支持注释、空行、通配符、目录规则和否定规则（`!`）。无法解析的规则必须写入导入报告，不得导致整个导入失败。

#### 导入报告

导入完成后展示：扫描文件数、纳入文件数、按原因统计的排除数量、不可读取列表、编码不支持列表、疑似敏感文件列表、符号链接列表和解析失败的忽略规则。

#### 重新扫描与文件状态

每个 FileRecord 至少保存相对路径、大小、最后修改时间和内容哈希。重新扫描时：

- 新增文件：创建新的 FileRecord，默认纳入下一次 Run。
- 内容哈希变化：标记为“已修改”，已有成功结果标记为“结果过期”。
- 文件删除：保留历史 Run 和结果，FileRecord 标记为“已删除”。
- 文件不可读取：标记为“不可读取”，不得创建新 Task。
- 文件改名：首期按“删除 + 新增”处理；可选使用内容哈希提示可能的重命名。
- 文件从纳入变为排除：历史记录保留，但不加入之后的 Run。
- 文件从排除变为纳入：创建或恢复 FileRecord，并显示纳入原因。

重新扫描不得自动重新执行任务。Task 入队前和实际发送前需再次核对文件哈希；若与 Run 快照不一致，Task 标记为“源文件已变化”，由用户选择跳过、使用 Run 创建时保存的快照，或创建新 Run 使用最新文件。


### 4.5 下部任务表格

一行代表当前视图中的一个文件配置或 Run Task。表格必须使用虚拟滚动，支持至少 10,000 行数据而不一次性渲染全部编辑控件。

| 列 | 名称 | 内容与操作 |
| --- | --- | --- |
| 1 | 文件 | 相对路径、树形层级、文件状态、大小、内容哈希短值和是否结果过期 |
| 2 | 提示词与模型 | 显示最终生效值及来源；编辑时通过侧边抽屉设置或清除单文件覆盖 |
| 3 | 返回结果 | 默认显示前 300 个字符；点击打开安全 Markdown 预览 |
| 4 | 请求信息 | 状态、实际模型、API 档案、Token、耗时、Attempt 数量、上下文版本和错误摘要 |
| 5 | 操作 | 根据状态显示执行、取消、重试、重新生成、恢复项目默认或查看历史 |

单文件配置规则：

- 未设置覆盖时显示“继承项目默认”，底层保存 `promptOverride: null` 或 `modelOverride: null`。
- 修改提示词或模型后标记为“单文件覆盖”，并提供“恢复项目默认”。
- Run 创建时计算最终值并保存不可变快照。
- 项目默认值后续变化不影响已创建 Run；对成功任务点击“使用最新配置重新生成”时，界面必须说明会产生新的 Task 版本或新 Run。

操作按钮随状态变化：

| Task 状态 | 可用操作 |
| --- | --- |
| 未执行 | 执行、排除 |
| 排队中 | 取消 |
| 处理中 | 取消请求、查看实时状态 |
| 成功 | 查看结果、重新生成、打开输出文件 |
| 失败 | 重试、使用最新配置重新生成、查看尝试历史 |
| 已取消 | 重新执行 |
| 已中断 | 重新排队、标记为结束 |
| 源文件已变化 | 跳过、使用旧快照、创建新 Run |

返回结果预览要求：

- 默认按 Markdown 渲染，可切换原始 Markdown。
- 清理危险 HTML，禁止脚本、事件属性和 `javascript:` 链接。
- 默认不自动加载远程图片或远程 iframe；用户点击后才能打开外部资源。
- 代码块仅作为文本展示，不提供直接执行能力。
- 关闭预览后保持表格筛选、滚动位置、列宽和选中状态。

### 4.6 筛选与批量操作

- 支持按 Task 状态筛选：未执行、排队中、处理中、成功、失败、已取消、已中断、源文件已变化。
- 支持按 FileRecord 状态筛选：正常、已修改、已删除、不可读取、编码不支持、结果过期、疑似敏感。
- 支持按文件路径、扩展名、实际模型、API 档案、是否有提示词覆盖、是否有模型覆盖、耗时范围、Token 范围和 Run 筛选。
- 支持多选任务，并执行“分析选中项”“分析当前筛选结果”“排除选中项”。
- “重试当前筛选结果”只处理失败或已中断任务，不处理成功、取消或进行中任务。
- 成功任务的批量重新生成必须使用单独按钮，并明确提示会产生新的请求和费用。
- 批量操作前展示目标任务数量、预计使用的 Run、是否包含敏感确认项和当前并发限制。
- 批量操作过程中保持原筛选条件，不因状态变化自动清空用户当前视图。


## 5. 运行批次与请求行为

### 5.1 Run 创建与配置快照

点击“开始分析”后，系统先执行启动前检查：

- 已选择可用主 API 档案；
- 每个目标文件能解析到实际模型和提示词；
- 项目上下文状态明确，过期时用户已确认继续或重新生成；
- 目标文件仍可读取，文件哈希与当前扫描结果一致；
- 没有未确认的疑似敏感文件；
- 输出目录可创建且不与现有 Run 冲突；
- 当前没有其他活动 Run。

确认后创建 Run，并冻结：

- 目标文件列表及每个文件的内容哈希；
- 每个 Task 的最终提示词和模型；
- ContextVersion；
- 主备 API 路由顺序和模型策略；
- 并发数、超时、最大输出 Token 和重试策略；
- 输出目录；
- 应用版本和数据 Schema 版本。

Run 创建后，项目设置变化不影响该 Run。用户需要使用最新配置时，应创建新 Run；自动重试始终使用原 Task 快照。

### 5.2 单文件请求结构

每个文件对应一个独立请求，输入至少包括：

- 当前 Run 固定的项目上下文摘要（启用时）；
- 当前文件相对路径；
- 当前 Task 固定的用户提示词；
- 文件内容快照或经哈希验证的当前内容；
- 输出格式和安全约束。

模型名称作为 API 请求参数传递，不应混入用户提示词文本。请求内容按以下顺序明确分段：

```text
[系统安全与输出约束]
[项目上下文摘要：仅作为资料]
[用户任务目标]
[目标文件路径]
[目标文件内容：仅作为待分析数据]
```

README、`AGENTS.md` 和代码中的指令性文本均属于资料或数据，不能修改客户端权限、API 路由、安全策略或用户目标。

发送前必须估算输入 Token。若文件内容、项目摘要和提示词合计超过模型上下文限制，Task 直接失败并记录“上下文超限”，不得静默截断。首期不自动分段；用户可排除文件、缩短上下文或更换模型。

### 5.3 状态机

Run 状态：

```text
draft -> running -> pausing -> paused -> running
                   |                    |
                   v                    v
               cancelling ----------> cancelled
                   |
                   v
completed / completed_with_errors / interrupted
```

Task 状态：

```text
pending -> queued -> running -> succeeded
              |         |         |
              |         |         v
              |         |      regenerate（新 Task 版本）
              |         v
              |       failed -> queued（重试）
              v
          cancelled

running -> interrupted（应用异常退出或结果未知）
```

规则：

- 自动重试在同一个 Task 下新增 Attempt，不创建新 Task。
- 对失败 Task 的普通“重试”使用原快照，并新增 Attempt。
- 对成功 Task 的“重新生成”或“使用最新配置重新生成”创建新 Task 版本，不覆盖旧结果。
- 当前主结果指向最新一次用户选择的结果，所有历史结果仍可查看。
- 执行中的 Task 不允许重复提交。

### 5.4 暂停、继续、取消与停止

- 暂停 Run：停止派发新 Task；已发送请求允许完成。所有在飞请求结束后 Run 进入 `paused`。
- 继续 Run：将尚未执行的 Task 重新加入队列，并继续遵守原 Run 快照。
- 取消单个 Task：排队中的 Task 直接取消；处理中的 Task 尝试中止网络请求。若服务端已完成但客户端未收到结果，标记为“已中断/结果未知”。
- 取消 Run：停止派发，将待执行 Task 标记为取消，并尝试中止在飞请求。
- 切换项目不暂停活动 Run；全局运行栏持续可见。
- 关闭应用时若存在活动 Run，必须提示用户取消退出或停止并退出。首期不承诺关闭主进程后继续后台执行。

### 5.5 崩溃恢复与重复计费保护

- Run、Task 和 Attempt 状态变化需先原子写入本地，再更新界面。
- 每个 Attempt 在发出网络请求前生成唯一 ID，并记录 `startedAt`。
- 应用异常退出后，原 `running` Attempt 标记为 `interrupted`，对应 Task 标记为“已中断/结果未知”。
- 重启后显示未完成 Run 和中断任务数量，不自动重新发送。
- 用户明确选择“重新排队”后才产生新 Attempt；界面需提示原请求可能已经被服务端计费。
- 同一项目配置和 Run 数据需使用进程级文件锁，避免多个客户端实例同时写入。
- JSON 文件使用临时文件写入后原子替换，并保留最近一个可恢复备份。

### 5.6 错误分类

| 错误类型 | 示例 | 自动重试 | 切换备用档案 |
| --- | --- | --- | --- |
| 网络类 | 超时、DNS、连接断开 | 是 | 当前档案耗尽后切换 |
| 限流类 | `429` | 是，优先 `Retry-After` | 耗尽后切换 |
| 服务端类 | `5xx` | 是 | 耗尽后切换 |
| 档案认证类 | `401`、账户级权限失败 | 否 | 是，并临时禁用档案 |
| 模型类 | 模型不存在、模型无权限 | 否 | 是，按备用模型策略 |
| 内容策略类 | 服务拒绝特定内容 | 否 | 默认否，仅当前任务失败 |
| 请求参数类 | 无效参数、协议不兼容 | 否 | 否 |
| 本地输入类 | 文件过大、编码失败、上下文超限 | 否 | 否 |
| 安全类 | 疑似密钥、路径逃逸 | 否 | 否 |
| 用户操作类 | 用户取消 | 否 | 否 |

所有错误必须使用结构化错误码保存，并将服务返回文本脱敏后展示。


## 6. 安全与隐私要求

### 6.1 源代码发送确认

- 首次使用某个 API 档案正式发送代码前，明确提示“文件内容将发送给该第三方服务”。
- 提示中展示档案名称和 Base URL，不展示 API Key。
- 用户确认结果按 API 档案保存；档案 Base URL 发生变化后需重新确认。
- 项目可显示最近一次确认时间，并允许用户撤销确认。

### 6.2 本地文件安全

- 默认不跟随符号链接、Windows Junction 或指向仓库外部的路径。
- 所有路径在读取和写入前必须规范化，并验证仍位于允许的根目录内。
- 输出文件名需处理 Windows 保留名、非法字符、超长路径和大小写冲突。
- 源文件只读打开，不修改时间戳、权限或内容。
- 临时文件不得包含 API Key；需要保存请求内容时，仅保存在项目 Run 输出中，并默认不保存完整源文件副本。

### 6.3 密钥与日志

- API Key 和敏感请求头只能保存在操作系统安全存储中。
- 普通配置、项目配置、Run、Task、Attempt、日志、错误信息和导出文件均不得包含明文密钥。
- 日志默认不记录完整代码、完整提示词或完整模型响应；调试模式需由用户明确开启，并说明可能包含敏感内容。
- 日志必须执行 Token、Authorization Header、Cookie、数据库 URL 等模式脱敏。

### 6.4 Markdown 与外部链接

- Markdown 渲染器必须禁用脚本执行和危险 HTML。
- 默认阻止远程图片、iframe 和自动下载。
- 外部链接通过系统浏览器打开前需显示域名确认，禁止 `file:`、`javascript:` 等危险协议。
- 模型返回内容不得触发客户端命令执行、文件写入或 API 配置修改。

## 7. 数据与输出

客户端全局数据、仓库项目配置和 Run 输出必须分开存储。

### 7.1 客户端全局配置

```text
<客户端配置目录>/
  projects.json              # 项目登记、路径、显示名称、最近打开时间
  prompt-library.json        # 预置和用户常用提示词
  api-profiles.json          # API 档案非敏感元数据
  app-settings.json          # 新项目默认值、窗口与界面设置
  locks/                     # 活动项目和 Run 的进程锁
```

API Key 和敏感请求头不进入上述 JSON，仅保存安全存储引用 ID。

### 7.2 仓库项目配置

```text
<仓库根目录>/
  .batch-analysis/
    project.json             # 项目设置、筛选规则和历史 Run 索引
    context.json             # ContextVersion、来源哈希和过期状态
    files.json               # FileRecord 索引、内容哈希和源文件状态
```

要求：

- 文件包含 `schemaVersion`。
- 每次修改使用临时文件 + 原子替换，并保留 `.bak`。
- 仓库不可写时，明确提示并降级到客户端配置目录中的项目专属存储。
- 不保存 API Key。
- 默认不保存完整源代码副本；仅保存文件哈希和必要元数据。
- `.batch-analysis/` 未被 `.gitignore` 排除时提示用户，不自动修改 `.gitignore`。

### 7.3 输出根目录与 Run 隔离

`outputRoot` 是项目级配置；每个 Run 在创建时生成独立目录：

```text
<输出根目录>/
  runs/
    20260715103825-run-a1b2c3/
      manifest.json          # Run 快照、整体统计和状态
      tasks.json             # Task 当前状态和版本关系
      attempts.jsonl         # 每次请求尝试，追加写入
      import-report.json     # 创建 Run 时采用的扫描报告摘要
      results/
        src/index.ts.md      # 保留原扩展名后再追加 .md，避免冲突
      history/
        <task-id>/           # 同一文件的旧结果版本，可选拆分存储
```

要求：

- 时间戳在 Run 创建时生成，精确到秒，并附加短 Run ID 防止同秒冲突。
- 写入前自动创建目录。
- 文本使用 UTF-8。
- 相对路径安全映射后仍需验证最终路径位于 `results/` 内。
- Windows 非法字符和保留名称使用稳定转义；发生冲突时追加路径哈希。
- 成功结果写入临时文件后原子替换。
- 失败或取消任务不创建空 Markdown 文件。
- API Key 不得进入任何输出文件。

### 7.4 是否保存请求内容

默认保存：

- 实际模型、提示词哈希、ContextVersion、文件哈希、Token、耗时、错误和结果。

默认不保存：

- 完整 API Key；
- Authorization Header；
- 完整网络请求 Header；
- 源文件完整副本；
- 可能包含敏感信息的原始服务错误体。

用户可在项目高级设置中选择是否把完整提示词快照写入 `manifest.json`。若关闭，只保存提示词哈希和常用提示词名称，但会降低结果可复现性，界面需说明。

## 9. 非功能要求

### 9.1 性能

- 10,000 个文件的项目可以完成扫描和表格展示，主界面不得长时间冻结。
- 文件扫描、哈希计算、Token 估算和磁盘写入在后台线程或工作进程执行。
- 任务表使用虚拟滚动，状态更新不得导致整表重绘。
- 大型 Markdown 结果按需加载，预览关闭后可释放内存。
- `attempts.jsonl` 采用追加写入，避免每次请求都重写整个历史文件。

### 9.2 可恢复性

- 项目配置、Run 状态和 Task 状态支持原子写入及备份恢复。
- 客户端重启后可恢复项目列表、筛选条件、历史 Run 和未完成 Run。
- 不因应用异常退出而自动重发可能已经计费的请求。

### 9.3 可观测性

- 每个 Run 显示总任务数、排队数、处理中、成功、失败、取消、中断、总 Token 和总耗时。
- 每个 Task 可追溯所有 Attempt、实际模型和 API 档案切换过程。
- 日志按级别记录客户端事件、扫描事件和请求状态，但默认不记录源代码全文。

### 9.4 兼容性

- 首发平台建议明确为 Windows 10/11 x64。
- 路径处理应兼容盘符、UNC 路径、中文路径和长路径；无法支持时必须提前提示。
- 所有持久化数据包含 `schemaVersion`，升级时提供迁移或只读打开旧版本的能力。

## 10. 验收标准

### 10.1 项目、扫描与文件变化

1. 选择目录和拖入目录生成一致的项目和文件列表。
2. 内置排除、递归 `.gitignore`、用户排除、二进制检测、编码检测、大小限制和敏感文件规则均生效，并能在导入报告中追溯原因。
3. 默认不读取仓库外部符号链接；构造 `../` 或链接路径不能逃逸仓库根目录。
4. 用户可以追加排除后缀和目录，无需重启应用。
5. 重新扫描能识别新增、修改、删除和不可读取文件；修改文件的旧结果被标记为过期，且不会自动重跑。
6. 文件在 Run 创建后发生变化时，发送前能够检测，并要求用户选择跳过、旧快照或新 Run。
7. 输出目录位于仓库内部时会警告并自动排除，避免分析结果递归进入下一次扫描。

### 10.2 提示词、上下文与单文件覆盖

8. 顶部 Tab 顺序固定为“提示词”“API 配置”，默认进入提示词页。
9. 用户可以选择、保存、编辑和删除个人常用提示词；选择常用提示词不会自动清除单文件覆盖。
10. 生成提示词可以基于用户目标和项目上下文生成候选内容，只有用户确认后才进入项目默认提示词。
11. 随机测试使用当前输入框提示词和项目默认模型，结果不进入正式 Run、进度或输出目录。
12. 新扫描文件默认继承项目提示词和模型，不复制冗余全文。
13. 单文件修改后保存覆盖值，恢复项目默认后覆盖值变为 `null`。
14. 项目级应用操作在清除单文件覆盖前必须二次确认。
15. 项目上下文可自动发现 README 和 `AGENTS.md`，可生成、预览、人工编辑和版本化；资料变化后能够标记过期。
16. Run 创建后固定 ContextVersion；自动重试不会混用新生成的上下文摘要。

### 10.3 Run、状态和恢复

17. 每次正式执行都会创建独立 Run，并冻结文件哈希、提示词、模型、上下文、API 路由、并发和重试配置。
18. 项目设置在 Run 执行期间发生变化时，不影响该 Run 中任何尚未开始的 Task。
19. 同一时间只能有一个活动 Run；切换项目不会中止活动 Run，且全局运行状态持续可见。
20. 并发设置为 5 时，所有在飞 AI 请求总数不超过 5；调低并发后不再派发新请求，直到降至新上限。
21. 暂停后不再派发新 Task，已发送请求可以完成；继续后从原队列恢复。
22. 取消 Run 会停止派发、取消排队任务并尝试中止在飞请求。
23. 客户端异常退出后，原处理中任务显示为“已中断/结果未知”，重启后不会自动重新发送。
24. 用户重新排队中断任务前会看到可能重复计费的提示。
25. 自动重试、主备切换和人工重试均保留独立 Attempt 历史，不覆盖旧请求记录。
26. 成功任务重新生成会产生新的 Task 版本，原结果仍可查看。

### 10.4 API、错误与主备切换

27. API Key 仅存在系统安全存储，普通配置、项目文件、Run 输出和日志中均不存在明文。
28. 用户可以测试、复制 API 档案；共享密钥引用和独立修改密钥的行为符合文档规则。
29. 主档案和多个有序备用档案可配置、排序、启停和选择模型策略。
30. 网络、`429` 和 `5xx` 按重试策略执行；优先遵循 `Retry-After`，耗尽后按顺序切换备用档案。
31. `401` 后当前 Run 的后续任务不会重复请求该失效档案。
32. `403` 能区分模型权限、账户权限和内容策略，不能一律按认证失败处理。
33. 参数错误、文件过大、上下文超限、敏感内容阻止和用户取消不会触发备用切换。
34. 所有档案失败后，任务详情能追溯档案、实际模型、耗时、状态码和脱敏错误。

### 10.5 输出、安全与性能

35. 每个 Run 拥有独立输出目录；同秒创建也不会发生目录冲突。
36. 结果路径经过安全映射，非法文件名、保留名和 `../` 不能写出 `results/`。
37. 成功结果使用 UTF-8 和原子写入；失败任务不创建空 Markdown 文件。
38. Markdown 预览不会执行脚本、危险 HTML 或 `javascript:` 链接，默认不自动加载远程资源。
39. 首次向某个 Base URL 发送代码前会要求用户确认；Base URL 改变后重新确认。
40. 疑似密钥文件默认被阻止进入 Run，错误和日志不展示命中的秘密原文。
41. 10,000 个文件可以完成扫描和虚拟表格展示，滚动和筛选可用，界面不会因一次性渲染所有编辑器而冻结。
42. 项目配置、Run 和 Task 文件采用原子更新；损坏时可从最近备份恢复或明确进入只读模式。
